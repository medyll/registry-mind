**Reviewer: Claude | Date: 2026-05-05 | Scope: End-to-end pipeline verification (runtime)**

## Health: 3 / 10 (functional)

Code compiles. UI renders. Room DB wired. **But the snap → capture → DB pipeline is fully broken.**
Status.md claimed "works end-to-end" — incorrect. Four blockers prevent any capture from being saved.

## CRITICAL — Pipeline Blockers (nothing reaches DB)

### P1 — SnapKeyService detection is a stub — never fires on hardware
```kotlin
// SnapKeyService.kt — isSnapKeyClick()
return event.className?.contains("SnapKey") == true ||
       event.packageName == packageName   // always false for hardware button
```
Oppo Find X9 physical Snap Key generates a `KeyEvent`, not an `AccessibilityEvent` with "SnapKey" class.
Detection never triggers. The overlay animation seen by user comes from elsewhere (LiquidButton).
**Fix:** Use `onKeyEvent(KeyEvent)` override in AccessibilityService and intercept the correct keycode.

### P2 — SnapKeyService → CaptureService bridge missing
`SnapKeyService.handleSnapKeyTrigger()` broadcasts `ACTION_SNAP_KEY_SINGLE`.
`CaptureService.onStartCommand()` listens for `ACTION_CAPTURE`.
No BroadcastReceiver connects these two actions. `OpenClawReceiver` handles unrelated signals only.
**Fix:** In `SnapKeyService.handleSnapKeyTrigger()`:
1. Start CaptureService with `ACTION_START` (if not running)
2. Send `ACTION_CAPTURE` to running CaptureService

### P3 — MediaProjection never initialized — capture always returns null
```kotlin
// ScreenCapturer.kt
if (mediaProjection == null) {
    continuation.resume(null)   // always hits this
}
```
`RegistryIngestor.initialize(mediaProjectionIntent)` must be called with result from
`MediaProjectionManager.createScreenCaptureIntent()` → user dialog → `onActivityResult`.
`CaptureService.onStartCommand(ACTION_START)` never calls `ingestor.initialize()`.
MediaProjection token is never obtained. Every capture returns null bitmap.
**Fix:** Add `ACTION_START` handling: launch `PermissionActivity` → get MediaProjection result → pass to `ingestor.initialize()` before starting foreground service.

### P4 — Service never starts from snap (chicken-and-egg)
UI says "Will start on next Snap Key press" — but SnapKey detection (P1) never fires, and even if it did,
nothing in the snap handler starts the service. P1+P2+P4 compound: snap → nothing → service stays stopped.

## Secondary — Tailscale decision not reflected in code

**Decision (2026-04-27 pivot):** Tailscale demoted, architecture is local-first.
**Code reality:** `DEFAULT_ENDPOINT = "http://mydde-pc.tail70869a.ts.net"` still hardcoded.
`isConfigured = SettingsManager.hasAuthToken()` — auth token required for "configured" badge.
In local-first mode, auth token + remote endpoint are optional (ExportConnector only).
Consider: `isConfigured` should check model ready + permissions, not auth token.
